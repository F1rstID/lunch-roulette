# Quick Task 001: 모바일 레이아웃 + 눈에 보이는 결함 3건 — Summary

## 결과

4개 탭이 320px 부터 가로 넘침 없이 그려진다. 데스크톱 배치는 결함 3건을 빼고 그대로다. 데이터 로직(`lib/`, `supabase/`) diff 0줄.

## 실측

측정 도구: gstack browse(Playwright Chromium), `viewport WxH` → `document.documentElement.scrollWidth`. 전(前)은 라이브(`lunch-roulette-umber.vercel.app`, main `7c43a81`), 후(後)는 이 브랜치의 로컬 프로덕션 빌드(`next build` + `next start -p 3100`, 라이브 Supabase 읽기). 측정일 2026-09-30.

|---|---|---|---|---|
| 390 (전) | 716 | 686 | 686 | 686 |
| 320 (후) | 320 | 320 | 320 | 320 |
| 390 (후) | 390 | 390 | 390 | 390 |

값은 페이지 `scrollWidth`(px). 뷰포트 폭과 같으면 가로 넘침이 없다.

라이브 데이터로 볼 수 없는 상태(확정 결과·회전 중·추첨 대기·랭킹 표·달력 기록·24자 이름·23자 메뉴)는 임시 확인 페이지에 가짜 데이터로 그려 같은 방법으로 쟀다. 그 페이지는 커밋하지 않고 지웠다.

## 확인하지 못한 것

- **실기기.** 측정은 전부 데스크톱 Chromium 의 뷰포트 에뮬레이션이다. iOS Safari 의 주소창 높이 변화, 포커스 확대, 실제 터치는 보지 못했다.
- **`pointer: coarse`.** 그 브라우저에서 흉내 낼 수 없어 같은 규칙을 주입해 배치만 확인했다.
- **회전 중 애니메이션.** 휠이 줄어든 상태의 실제 회전은 보지 못했다. `transform-origin` 이 viewBox 좌표라는 것은 리뷰가 계산값으로 확인했다.
