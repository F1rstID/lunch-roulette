# 주간 제외 + 실제 방문 기록

## 문제

룰렛이 순서(1·2·3순위)를 뽑는 것까지는 라이브(0006). 남은 공백 둘.

1. 팀이 2순위로 가도 앱은 모른다. 기록 탭·랭킹은 "1순위 당첨" 만 남긴다.
2. 12시에 줄을 보고 "어디 가지?" 를 매번 입으로 정한다. "오늘은 여기로 간다" 는 공통 상태가 없다.

그리고 지겨운 매장이 계속 나오는데, 지우거나 매일 말없이 빼는 것 말고 방법이 없다.

## 결정

1. **하루 한 행.** 날짜마다 "목적지" 와 "방문 확인" 을 갖는 행 하나(가칭 `lunch_days`). `results` 는 그대로 추첨 결과만 담고 덮어쓰지 않는다.
2. **목적지 기본값 = 1순위.** 아무도 안 눌러도 그날 목적지는 `ranking[0]`. "웨이팅 있어요 → 다음 식당" 을 누르면 목적지가 그 매장으로 바뀌고 모든 탭에 보인다. 되돌리기 가능.
3. **방문 확인은 선택.** "여기서 먹었어요" 를 누른 날만 확인됨. 안 누른 날은 기록 탭에 **"확인 안 됨"** 으로 구분해 보인다 — 당첨에서 방문을 추정해 과거를 채우지 않는다(Codex). 단, 제외 판정(아래 4)은 목적지를 쓴다 — 0클릭이어도 제외가 돌아가야 기능이 조용히 죽지 않는다.
4. **이번 주 제외 목록 = 월~어제의 목적지 ∪ "이번 주 쉬기" 누른 매장.** 들어오는 경로는 둘(자동 방문·수동 쉬기), 나가는 경로는 하나 — **월요일 00:00 KST 전부 해제.** Codex 제안 4(매장 쉬기)와 6(방문 기준 cooldown)은 이 하나로 합친다.
5. **`settings.cooldown_days` 폐기.** "최근 N일 당첨 제외" 는 주간 규칙으로 대체. `_shared/cooldown.ts` 는 `[이번 주 월요일, 어제]` 창으로 바뀐다 — 오늘은 창에 안 들어간다(지금과 같다 — 다시 돌리기가 오늘 목적지를 다시 뽑을 수 있어야 한다). 월요일엔 창이 비어 전원 후보. 제외 뒤 후보 0개면 지금처럼 전체 후보로 폴백하되, 쉬기 매장을 몰래 되살리는 폴백은 두지 않는다(Codex 경고) — 전멸 시에는 사용자에게 "이번 주 제외가 전부라 전체에서 뽑았어요" 를 보인다.
6. **제외 매장은 휠에서 빠진다.** 후보 목록에는 흐리게 남기고 사유를 적는다("화요일 방문" / "이번 주 쉬기"). 지금은 쿨다운 매장도 휠 칸을 차지해 표시 확률이 실제 pool 과 다르다(Codex 평가 C5) — 이 변경으로 함께 해소된다.
7. **2·3순위 지도 버튼**(Codex 제안 3)은 같은 결과 카드라 묶어 넣는다.
8. **기록 탭·랭킹은 목적지 기준.** "확인 안 됨" 표시 구분. 기존 당첨 기준 집계는 보조 전환으로만.

## 범위 밖(이번 Phase 아님)

- 👍👎 "다음에도 갈까요?" → `.planning/seeds/thumbs-vote.md`. 방문 확인 버튼이 실제로 눌리는지 본 뒤.
- 좋아요·방문 간격 가중치 → 보류. 제외 뒤 남은 매장은 같은 확률.
- Codex 품질 평가(`.context/codex-eval-2026-10-06.md`)의 Realtime 재조회 복구(C1)·설정 fail-closed(C3) 등은 별건. 단, 아래 제약 참조.

## 제약·주의

- **Realtime 누락.** "다음 식당" 은 공통 상태라 이벤트를 놓친 탭은 다른 목적지를 보인다. 이 Phase 의 `lunch_days` 구독에는 최소한 `visibilitychange`·재연결 시 재조회를 넣는다(C1 의 부분 적용). 나머지 구독까지 넓히는 건 별건.
- **익명.** 누구나 목적지를 바꾸고 쉬기를 누른다. 막지 않고 되돌리기를 준다(Codex). 변경 사실을 화면에 밝힌다("○○님" 없이 "방금 바뀜").
- **핀 매장과 쉬기 충돌.** 핀 매장은 자정 리셋이 자동으로 후보에 넣는다. 쉬기 중인 핀 매장은 후보 목록엔 들어오되 제외 표시 + 휠에서 빠지는 쪽이 자연스럽다 — 계획 단계에서 확정.
- **"다른 매장" 선택.** 목적지가 카탈로그 밖(없는 매장)일 수 있다. 이름 스냅샷만 저장, 제외 판정에는 매장 id 가 있을 때만 참여.
- **월요일 경계.** 주 시작 계산은 `_shared/kst.ts` 의 KST 분해 위에서 한다. 로컬 `Date` 요일 메서드 금지.
- **적용 순서.** 0007 SQL → 함수 2종 배포 → 머지(0005·0006 과 같은 순서). README 에 절 추가.

## 계획 단계에서 정할 것

- 쉬기 버튼 위치(매장 탭 / 오늘 후보 목록 / 둘 다)와 문구.
- `lunch_days` 행 생성 시점 — 추첨 함수가 만들지, 첫 클릭 때 클라이언트가 만들지(목적지 기본값을 어디서 "저장" 하느냐의 문제. 저장 안 하고 `ranking[0]` 파생으로 두는 쪽이 단순).
- 쉬기 저장 위치 — `restaurants.paused_week`(주 시작 날짜) 컬럼 vs 별도 표.
- "확인 안 됨" 의 랭킹 포함 여부(목적지 기준 포함 + 라벨 vs 제외).
