**`invoke()` 반환의 진실(RESEARCH §Q-3, 설치본 소스 직독 + 레포 tsc 5.9.3 실측):**
`const { data, error, response } = await supabase.functions.invoke<RespinResponse>("respin-roulette")` 에서 `data: RespinResponse | null` · `error: any` · **`response: Response | undefined`**. 구현은 non-2xx 에서 본문을 읽기 **전에** `throw new FunctionsHttpError(response)` 하고 `catch` 가 `{ data: null, error, response: error.context }` 를 돌려준다(`FunctionsClient.js:258-291`) → `response` 는 `error.context` 와 **같은 미독 `Response`** 다. 따라서 값 import 없이, `any` 를 한 번도 거치지 않고 본문을 정확히 한 번 읽을 수 있다. `error` 는 `any` 이므로 `error instanceof Error ? error.message : String(error)` 로 좁힌다.
**전제 조건:** 500 응답에 `Access-Control-Allow-Origin` 이 있어야 한다. 없으면 브라우저가 응답을 차단하고 supabase-js 는 `FunctionsFetchError` 를 주며 `response` 가 `undefined` 가 된다 → 본문이 영원히 안 보인다. 그래서 Task 3 의 "모든 반환이 `json()` 을 지난다" 가 Task 2 의 전제다(현행 코드도 이미 그렇다).
